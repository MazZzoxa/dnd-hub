# D&D Hub v1.0.5 — Import Sync IDs & Large Bio Image Fixes

This maintenance release fixes campaign linking for imported characters and resolves an Android issue that could prevent the character list from loading when a Bio contained a large image.

### Fixed

- Fixed `Bad state: Sync entity has no sync_id` when a player tried to link an imported character to a campaign. Missing sync IDs are now generated for nested character records before sending them to the GM, including items, spells, abilities, attacks, notes, spell slots, XP history, custom actions and conditions.
- PDF and `.dndhub` imports now assign sync IDs to imported records. Characters imported before this fix can be linked to a campaign without being imported again.
- Fixed an infinite loading indicator on Android when a character Bio image was several megabytes in size. Large images are stored separately in `character_images` and read in chunks; the main character record keeps a thumbnail up to 256 px for lists and avatars.
- Removed the previous 8 MB application-level limit for Bio images.
- Existing databases are migrated automatically on first launch. Previously affected image records are recovered without requiring a database reset or re-import.
- Character updates such as HP or XP changes no longer overwrite the Bio image. The image is changed only through the Add, Replace and Delete image controls.
- Avatar decoding now targets the required display size to reduce memory usage. If character-list loading still fails, the loading indicator no longer spins indefinitely and the error is written to the log.

### Export & backup

- Full Bio images are included in character `.json` and `.dndhub` exports, as well as backup/restore.

### Notes

- Bio images are not synchronized to the GM over LAN and are transferred through character files or backups only.
- The GM-mode PDF character card uses the Bio thumbnail rather than the full-size image.
