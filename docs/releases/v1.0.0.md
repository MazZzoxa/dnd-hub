# D&D Hub v1.0.0 — Core Gameplay

Major gameplay release for D&D Hub. This update completes the core gameplay loop defined by the project plan and extends the existing Character, Campaign, Session, Battle and LAN sync systems with persistent Gameplay State.

## Features

- Character life state: `normal`, `downed`, `dead`
- HP reaching zero moves a normal character to `downed` without automatically marking the character dead
- GM-controlled life-state changes with `Downed → Normal` and revival flows
- Death Saves retained as a separate mechanic
- Persistent Character Conditions with source, duration, remaining rounds, scope, activity and metadata
- Conditions can be applied or removed through GM commands and approved Battle Actions
- Improvised Actions using the existing `BattleActionType.manual` path
- One-time improvised actions and saved Custom Actions with reusable attack/effect formulas
- GM XP, currency and Inspiration grants
- Copper, Silver, Electrum, Gold and Platinum reward support
- Authoritative GM commands for HP, temporary HP, XP, currency, Inspiration, Conditions and life state
- Expanded Session History for rewards, Conditions, Downed, Death, Revival and Battle gameplay events
- Character Sheet and Battle UI display Gameplay State and active Conditions
- Dice Roller is available from the character list and inside the character sheet
- Temporary HP can be added, reduced and set to an exact value directly from the character sheet
- Custom Actions and Conditions included in local backup, character export/import and campaign synchronization snapshots
- Database migration to v16 for the new Gameplay State entities
- Player can unlink their own character from a campaign without leaving the campaign
- Characters linked to campaign players are hidden from the GM's main local character list
- Battle Actions reliably load for both GM character views and the player's own character view

## Architecture

```text
GM
 ↓
Authoritative Command
 ↓
GM Server / Local State
 ↓
Character / Condition / Reward State
 ↓
Battle Journal + Session History
 ↓
SQLite Replicas + Sync
```

The v1.0 implementation keeps the architectural boundaries from the project plan: `Character` is persistent character state, `Battle` is temporary combat state, `BattleActionRequest` is an action intent, `CustomAction` stores user-defined action data, `CharacterCondition` stores active effects, `SessionReward` represents GM-issued progression/reward changes and `SessionHistory` presents the session timeline.

Conditions are intentionally not implemented as a full D&D Rules Engine. The GM remains the rules authority while the server remains the authority for synchronized gameplay state.

## Scope

This release does not introduce NPC, Quest, Location, Faction, World, AI or a full automatic D&D Rules Engine. Those systems remain outside the v1.0 scope.
