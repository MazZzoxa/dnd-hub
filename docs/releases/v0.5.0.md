# D&D Hub v0.5.0 — Local Networking MVP

This release starts the networking layer described by `docs/networking-v0.5.md`. The first shipped milestone is the LAN/WebSocket path: Windows GM starts a local FastAPI server, Android Player discovers the session over UDP and joins it through WebSocket.

## Implemented

- Transport-independent network message envelope (`protocol`, message type, IDs, campaign ID, optional sequence).
- Stable `sync_id` fields for shared entities while keeping local SQLite integer IDs.
- Database migration from schema v8 to v9 with automatic sync IDs for existing records.
- `ConnectionManager` and `HubTransport` abstractions.
- LAN discovery via UDP broadcast on port `42817`.
- Local GM server on FastAPI/WebSocket on port `8765`.
- Random invite token validation and campaign/session validation.
- `Host Game` and `Find Game` UI flows.
- QR invite generation plus manual connection fallback.
- Basic `ping/pong`, join/leave events, acknowledgements and character update events.
- Character quick changes (HP, XP, gold, proficiencies, inspiration and death saves) publish through the sync service while connected.
- Remote character update application into the local SQLite replica.
- Server-side duplicate command protection and bounded event history.
- Wi-Fi P2P and Bluetooth transport interfaces reserved for later phases without coupling them to sync.

## Current boundary

This is the LAN MVP of v0.5. The authoritative shared campaign store, full snapshot/replay persistence, native Windows/Android Wi-Fi Direct bridge, Bluetooth fallback and final standalone packaging of the Python runtime are not presented as complete in this milestone.
