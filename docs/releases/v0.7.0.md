# D&D Hub v0.7.0 — Extended Session Workspace

Major gameplay-tools release for D&D Hub. This update turns `Session` into a persistent workspace for running a specific game session while keeping Battle as a separate workspace inside the Session.

## Features

- Session Workspace for GM and Player
- Session Journal with independent editable notes
- Session Events for gameplay events
- XP Rewards linked to the existing Character XP / XP transaction system
- Loot with `available → claimed` workflow before an item is added to Character Inventory
- Atomic GM commands for XP rewards and Loot claiming
- Unified Session History aggregated from Session Events and the existing Battle Combat Journal
- Battle history is grouped into one expandable entry per battle
- GM can name each battle when starting it
- Character target pickers are limited to player characters linked to the current campaign
- Session Overview shows note, event, loot, battle and level-up statistics
- Session participants can open a detailed read-only character sheet directly from the Overview
- Session start, resume, finish, and Battle start/finish represented in Session History
- Persistent `sync_id` for all new Session workspace entities
- LAN synchronization and authoritative GM Server support for Notes, Events, Rewards and Loot
- GM write access with Player read-only Session Workspace access
- Database migration from legacy `Session.notes` into a Session Note while keeping the legacy field for compatibility
- Session workspace data included in campaign snapshots and reconnect recovery

## Architecture

The release adds four Session-scoped entities:

```text
Session
├── Session Notes
├── Session Events
├── Session Rewards
├── Session Loot
└── Battles
    ├── Turns
    ├── Action Requests
    └── Combat Journal
```

XP and Inventory remain the existing sources of truth. Session Rewards provide the gameplay context and the server command applies the corresponding XP transaction atomically. Loot is separate from Inventory until it is claimed.

## Decisions for v0.7

- `SessionEvent` is append-only in the current UI; there is no separate edit/delete workflow.
- `Session History` is assembled at read time instead of stored as a second log table.
- Battle details are grouped at the presentation layer; existing Battle Log entries remain the source of truth.
- Loot uses the minimal `available → claimed` workflow.
- XP is the first supported reward type; other reward types are deferred.

## Permissions

GM can create and edit Session Notes, create Events, award XP, create/edit available Loot, claim Loot for a campaign character, and inspect the unified Session History. Player receives read-only Session Workspace access.

## Scope

This release does not introduce a global NPC, Quest, Location, Faction, Relationship, Map, world simulation or AI system. Session-local NPC/Quest information can still be represented through Notes or Events.
